Once an interaction object has been defined, it is tempting to design an architecture that emits
it directly.  The difficulty is that semantic requirements become information constraints.  If an
edge is claimed to be invariant under substitutions at its endpoints, then the mechanism choosing
that edge cannot depend on those endpoint values.  If a zero edge is claimed to save computation,
the implementation must actually skip its work.  If an update is claimed to descend an energy,
its memories, state variables, and parameter tying must satisfy the assumptions of the descent
proof.

These constraints are easy to blur because neural architectures combine several roles in one
tensor.  An attention coefficient can select a route, scale a message, and contribute to an output
response.  A pair representation can store persistent state or merely cache a transient feature.
A soft gate can express uncertainty without producing exact support.  The operator framework
separates these roles before asking which implementation is efficient.

The next two chapters develop complementary results.  This chapter treats routing geometry,
persistent relational state, operator reuse, ordered composition, sparse execution, and structural
alignment.  These are capacity and systems questions.  Chapter
\ref{chap:book-conditional-limits} then treats endpoint-removable context, strict targetwise
support, affine deletion, and optional MSA supervision as measurability and information questions.

The separation matters because representational capacity does not settle conditional meaning.  A
router may compute an accurate adaptive graph while reading evidence that a later endpoint
intervention is supposed to hold fixed.  Conversely, withholding endpoint identities can create an
irreducible prediction floor even for a high-capacity architecture.

Realizability marks the boundary between a mathematically well-defined interaction and a trainable
mechanism that can infer or execute it under finite information and compute.  This chapter begins
with capacity and execution; the next chapter isolates the information contract.
